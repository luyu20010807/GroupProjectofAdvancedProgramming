# 五名成员个人实验报告差异化写法

全组可以使用同一项目代码和总体背景，但五份报告不能完全相同。每个人应突出自己的模块、真实交互、测试和 Git 证据。

## 组长报告

- 功能介绍：总体架构、跨商家拆单、订单/售后状态机、集成发布。
- 系统设计：架构图、状态图、事务边界、公共接口。
- 测试：完整流程和跨模块集成。
- 协作：任务拆分、公共表评审、PR 审核、冲突处理、Release。

## 成员A（用户端）

- 功能介绍：商品、购物车、订单、售后、通知、PWA。
- 系统设计：响应式布局、状态驱动按钮、重复提交防护。
- 测试：移动端尺寸、表单边界、错误提示、用户越权。
- 截图：商城首页、购物车、订单详情、售后进度。

## 成员B（商家端）

- 功能介绍：商品/库存、订单履约、售后审核、退货验收。
- 系统设计：商家数据隔离、发货前置条件、审核截止时间。
- 测试：跨商家越权、库存边界、拒绝理由、重复发货。
- 截图：商品管理、待发货列表、售后工作台。

## 成员C（管理员端）

- 功能介绍：RBAC、平台仲裁、账号治理、商品治理、审计、超时任务。
- 系统设计：权限矩阵、审计字段、自动升级策略。
- 测试：客服/业务/技术管理员的正向和反向权限。
- 截图：平台概览、仲裁中心、审计日志、账号列表。

## 成员D（小程序与测试）

- 功能介绍：Token API、小程序商品/购物车/订单/退款、Pytest、Locust。
- 系统设计：Session 与 Token 区别、API Schema、测试分层。
- 测试：接口认证、Token 无效、API 与 Web 数据一致性、压力测试。
- 截图：微信开发者工具页面、Pytest 输出、Locust 结果。

## 不能共用的证据

- 个人 AI 对话必须是本人真实对话。
- Git 提交截图必须显示本人账号。
- 本人测试截图应对应本人负责模块。
- “我完成了”只能写实际由本人完成或深度修改、测试、审查的内容。
