# 星河商城：多端电商业务闭环课程项目

本项目是一个以“业务流程深度”为核心的电商平台课程作业。后端使用 Python FastAPI 与 SQLite；普通用户网页端采用响应式 PWA，可作为桌面网页和可安装轻量 APP；同时提供微信小程序源码；商家后台和平台管理员后台使用独立导航、独立权限与独立业务视图。

## 一、已实现的核心业务

1. 用户侧：商品检索、商品详情、购物车、跨商家自动拆单、模拟支付、订单取消、确认收货、仅退款、退货退款、售后催办、填写退货物流、申请平台介入、站内通知。
2. 商家侧：本店商品增改上下架、库存维护、本店订单查看、支付后发货、填写物流单号、售后同意/拒绝、确认退货收货与退款。
3. 平台侧：超级管理员、客服管理员、业务管理员、技术管理员四类角色；售后仲裁、账号停用、商品治理、超时巡检与审计日志。
4. 系统机制：订单状态机、售后状态机、角色权限校验、商家处理超时自动升级、用户退货超时关闭、商家确认收货超时自动退款、通知和审计记录。
5. 多端：用户响应式网页/PWA、微信小程序、商家后台、管理员后台，共用同一数据库和 API。

## 二、运行环境

- Python 3.10–3.13
- Windows、macOS 或 Linux
- 无需 MySQL、Redis、Node.js 或 Java

## 三、Windows 一键运行

双击 `run.bat`。首次启动会自动：

1. 创建 `.venv` 虚拟环境；
2. 安装依赖；
3. 创建 SQLite 数据库；
4. 写入演示用户、商品、订单和售后数据；
5. 启动 `http://127.0.0.1:8000`。

也可以手工执行：

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python run.py
```

Linux/macOS：

```bash
bash run.sh
```

## 四、演示账号

所有账号密码均为 `123456`。

| 账号 | 角色 | 主要演示内容 |
|---|---|---|
| `user1` | 普通用户 | 下单、支付、确认收货、退款、催办、平台介入 |
| `merchant1` | 数码商家 | 商品、发货、售后审核、确认退货 |
| `merchant2` | 生活商家 | 跨商家拆单和另一商家独立履约 |
| `admin` | 超级管理员 | 全部平台能力 |
| `service` | 客服管理员 | 售后仲裁，不可修改账号或查看技术审计 |
| `business` | 业务管理员 | 账号、商品治理、售后与审计 |
| `tech` | 技术管理员 | 审计日志，不可裁决退款 |

## 五、推荐演示路线

1. 使用 `user1` 登录，将两个不同商家的商品加入购物车并结算，观察系统自动生成两张订单。
2. 用户完成模拟支付；切换 `merchant1` 登录，在订单履约中填写物流单号发货；再切回用户确认收货。
3. 用户在已支付/已完成订单中申请售后；切换商家同意或拒绝。
4. 商家同意退货后，用户填写退货物流；商家确认收货后系统完成模拟退款。
5. 商家拒绝后，用户申请平台介入；切换 `service` 或 `admin`，在仲裁中心查看双方证据并裁决。
6. 使用管理员执行“超时巡检”，验证商家审核超时、用户寄回超时、商家收货确认超时三类兜底。
7. 使用 `tech` 登录审计日志，验证每次状态变化均记录操作者、对象、前后状态和说明。

## 六、自动测试

```bash
pip install -r requirements-dev.txt
pytest
```

当前自动化测试共 10 个，覆盖：跨商家拆单、完整履约、网页集成、仅退款、退货退款、商家拒绝与平台介入、商家越权、管理员越权和三类超时任务。

压力测试：

```bash
python run.py
# 另开终端
locust -f load_test/locustfile.py --host http://127.0.0.1:8000
```

浏览器打开 `http://127.0.0.1:8089` 配置并发用户数。

## 七、微信小程序运行

1. 先启动后端。
2. 微信开发者工具导入 `miniprogram` 文件夹。
3. 本地演示可使用 `touristappid`，并在“本地设置”勾选“不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书”。
4. 模拟器使用 `http://127.0.0.1:8000`；真机调试需把 `miniprogram/app.js` 的 `baseUrl` 改为电脑局域网地址，例如 `http://192.168.1.10:8000/api/v1`，手机与电脑需处于同一网络。
5. 正式发布必须配置已备案 HTTPS 域名，不能使用 HTTP 或局域网地址。

```text

  main.py                 FastAPI 应用入口
  models.py               数据表与关系
  dependencies.py         登录态、API Token 与 RBAC
  routers/                用户、商家、管理员和小程序 API
  services/               订单、售后、通知与审计领域服务
  templates/              三类角色的 Jinja2 页面
  static/                 PWA、CSS、JS 与离线 SVG 商品图

scripts/                   演示数据和超时任务脚本
tests/                     单元与集成测试
load_test/                 Locust 压力测试
docs/                      业务、协作、测试和报告资料
agents.md / rules.md       AI 协作配置
skills/                    业务分析、后端、测试、报告技能说明
```

## 九、重置演示数据

停止应用后运行：

```bash
python scripts/seed_demo.py --reset
```

不要把 `ecommerce.db` 提交到 GitHub；数据库由种子脚本自动生成。

## 十、安全说明

本项目适合课程演示，不应直接用于真实交易。真实生产系统还需接入正式支付、对象存储、风控、验证码、HTTPS、CSRF 防护、密钥管理、数据库迁移、消息队列、监控告警和合规审计。
